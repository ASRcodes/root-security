## What changed for this submission

- Replaced unsafe-looking live-domain demo strings with shared reserved `.example` inputs. Sample selection, copying and sharing never scans automatically. Scanning uses the real pipeline and shows expected local behavior alongside the input.
- Kept normal, caution, unconfirmed local high-risk and Google reputation states distinct. Reserved examples carry **Harmless example · local rule check**, with no Google verification claim and no guardian action.
- Preserved the retired URL forest as a diagnostic asset. Local high-risk findings depend on corroborating rules and remain unconfirmed; an offline or failed provider check does not become a clean result.
- Call Shield now uses caution for unfamiliar/international caller IDs supplied by Android, stronger wording only for a user's local report, and report-management controls. Android normally excludes saved contacts and hidden/restricted numbers from screening. A report is not independently verified fraud intelligence. Caller ID can be spoofed.
- Kept call warnings subject to role, settings, overlay permission and emergency-priority handling; pausing or resetting protection must not silently re-enable call warnings.
- Kept encrypted scan history and saved API-key storage separate from private-preference caller reports and the cloud family-SOS flows.

## Submission checklist

- Build from the new root-security checkout and record its revision. Future changes belong in that repository; preserve the old DontMissMOM checkout as historical context.
- Record the final APK's SHA-256 after signing/alignment verification. Install that same artifact for the rehearsal without clearing user data.
- Run the final JVM and appropriate emulator suites. Tests that reset data must never run against a user's phone.
- Rehearse the exact normal, caution and local high-risk examples in [Demo script](DEMO_SCRIPT.md). Verify the harmless-example label and absence of guardian actions.
- If presenting Google's test URL, record an actual provider match and attribution. If the response is Not checked, say that online checking is unavailable; use the separate labelled local example or preview instead.
- If presenting incoming-message/call interception, observe the actual event on the target phone. Check notification previews, the call-screening role, notification permission and any overlay configuration first.
- Show SOS only with consenting demo accounts/recipients. Service acceptance is not proof of recipient delivery or audible playback; observe the receiver if claiming that behavior.
- Confirm no API key, Firebase configuration, signing credential or service-account file is committed. Firebase setup belongs in ignored `app/google-services.json`; the optional Safe Browsing key is entered on the phone.

## Judge-ready statement

“root-security connects everyday scam guidance with family help in one Android app. Local rules and a local text model explain risk signals; optional Google reputation adds known-threat information. We show the source and uncertainty of a warning, keep protection history on the phone, and make emergency sharing a separate action. Our evidence is the specific tests and emulator demonstrations recorded here—not a universal detection-accuracy claim.”

## Boundaries to state clearly

This prototype does not hear call audio, identify cloned voices, certify links as safe, inspect every message, guarantee an Android full-screen launch, perform complete antivirus scanning or guarantee emergency delivery. Unknown numbers and country prefixes alone do not prove fraud. The reported-caller list is private app preference data, not encrypted scan history or a shared threat database.

Longer-term work is representative false-positive/missed-threat evaluation, language/user-comprehension testing, dependable device delivery, production credential/deployment design and commercial threat-service licensing. A clean demo does not substitute for those evaluations.
